## Fix soon

**F-1. The installed PWA runs without the Content-Security-Policy.**
`backend/config/settings.py` (MIDDLEWARE order), `frontend/vite.config.ts` (workbox).
WhiteNoise sits before `ContentSecurityPolicyMiddleware` and `XFrameOptionsMiddleware`, so every
file it serves (including `/app/index.html`, `/app/sw.js`, all assets) has no CSP and no
`X-Frame-Options`. The service worker precaches `/app/index.html` and answers every in-app
navigation from that copy (`navigateFallback`), so after the first visit the signed-in app's
document never carries `script-src 'self'` (auth.md §7.7). No HTML-injection sink exists in
`frontend/src` today, so this is defence in depth, not an open XSS.
Fix: move the CSP and X-Frame-Options middleware above `WhiteNoiseMiddleware` (they then wrap
its responses), or set `WHITENOISE_ADD_HEADERS_FUNCTION` to add both to `.html`; test that
`GET /app/index.html` carries the CSP; add the check to `scripts/golive-smoke.sh`.

**F-2. Anonymous requests can make the web container parse 40 MB bodies.**
`backend/config/settings.py` (`DATA_UPLOAD_MAX_MEMORY_SIZE = 40 MiB`, global).
A form POST to `/` with any well-formed `csrftoken` cookie and a matching Referer is read and
parsed by `CsrfViewMiddleware` before the view or any rate limit: a 30 MB body took 423 ms and
grew the web container by about 60 MB (4 ms and nothing without the cookie). Gunicorn runs 8
threads and `web` has `mem_limit: 768m`, so a handful of parallel requests can push it towards an
OOM kill. Availability only. The upload chunk endpoint doesn't need the setting:
`uploads.receive_chunk` reads with `request.read()`, which `DATA_UPLOAD_MAX_MEMORY_SIZE` doesn't
cover; the largest JSON body (10,000 drawn points) is well under 1 MB.
Fix: put `DATA_UPLOAD_MAX_MEMORY_SIZE` back to about 2.5–5 MiB, keep `production_problems`'
check, and test that a 32 MiB chunk still uploads and an oversized form POST to `/` answers 400
cheaply.

**F-3. Removing someone's access doesn't end their session, and there's no deactivate command.**
`docs/go-live.md` ("Adding a family member", last paragraph), `backend/travel/accounts/`.
The runbook says removing the user from `travel-users` refuses "every new sign-in", but an
existing session stays valid for `DJANGO_SESSION_AGE` (14 days), and nothing in the app or the
`./dev prod manage` commands sets `is_active = false` (deactivation itself works: a deactivated
account's session answered 401 in the spot check). Today the only way is SQL as the owner.
Fix: a `deactivate_account <id>` command like `set_role` (owner role, dry run, deletes the
account's sessions as `rebind_identity` does, audit row); add "deactivate in the app" to the
runbook's removal step and to the lost-phone case.

**F-4. The second factor rests on Authentik's flow alone until a real token is seen.**
`backend/travel/accounts/provisioning.py` (`shows_second_factor`), D-103.
A token without `amr` passes. 40c-1's Authentik facts came from Authentik's main branch, not the
deployed version. If the deployed Authentik omits `amr`, a flow without an Authenticator
Validation stage would let a password alone in and the app couldn't tell.
Fix: in 40c-2/40c-3, decode Adam's real ID token claims (names only, no values in logs) and
confirm `amr` lists `mfa` or `user`. If it does, add a production setting (for example
`OIDC_REQUIRE_AMR=true`, required by `production_problems`) so a token without `amr` is refused.
If it doesn't, record that 2FA is enforced only by the flow and add a password-only negative test
to the runbook's step 1.5.

**F-5. The dev server was reachable through the tunnel (2026-11-01 to 2026-11-17).**
`docs/design/threat-model.md`, `docs/decisions.md`, `docs/go-live.md`.
What it exposed: with `DEBUG=true` and no guard, a request with `Host: travel.adamcasada.com`
got Django's technical error page for the refused host (status 400), which shows the settings
and the request environment (runserver passes the container's environment variables). Django
masks names containing API, AUTH, TOKEN, KEY, SECRET, PASS or SIGNATURE, so the dev secret key,
database passwords, the OIDC client secret and the ORS key were shown as stars; LAN addresses,
role and database names, paths and the dev client id were visible. If the dev
`DJANGO_ALLOWED_HOSTS` listed travel.* at the time (the current `.env` doesn't), the landing
page and DEBUG 404 pages (URL list) were served too. Data was not reachable from outside: sign-in
needs the mock provider, which is LAN-only, and the API needs a session. cloudflared logs only
failed requests, so whether anyone visited can't be known. Production's secrets were generated
afterwards (40a, 2026-11-18) and are unaffected.
Fix: record the incident and its window in the threat model and decisions log; ask Adam whether
dev's `DJANGO_ALLOWED_HOSTS` named travel.* then; rotating dev's secret key and DB passwords is
optional (they were masked). In `docs/go-live.md` step 2, verify the tunnel change from
cloudflared's own "Updated to new configuration" log line (travel.* and trips.* →
`http://localhost:8784`, no `httpHostHeader`, no rule to 8780) rather than from memory of the
dashboard; keep `~/infra/TUNNELS.md` in step with it.

**F-6. The production base image is behind Debian security updates.**

re-run the CPU smoke test (no AVX).

## Minor

**F-7. A Bearer header gets past the login wall to Ninja's docs and schema, and a bad token
answers 500 when Authentik is unreachable.** `backend/travel/core/loginwall.py`,
`backend/config/api.py`, `backend/travel/accounts/oidc.py`. With any `Authorization: Bearer x`,
anonymous `GET /api/v1/docs` and `/api/v1/openapi.json` answer 200 (the smoke's "schema not
public" check sends no header). The schema is in the public repo, so nothing new leaks. With the
provider unreachable, `/api/v1/me` with a junk token answered 500 (`metadata()` raises
`requests` errors that `validate_access_token` doesn't catch), and every such request retries
discovery. Fix: `NinjaAPI(docs_url=None)` in production (or a `docs_decorator` requiring a
session; `export_openapi` doesn't need the URL); treat `requests.RequestException` in
`OidcBearer` as "no user"; add both to the smoke.

**F-8. A loopback Host header through the tunnel skips the scope guard.**
`backend/travel/core/exposure.py` (`is_reachable`). `Host: localhost` or `127.0.0.1` with
`X-Forwarded-Proto: https` and `CF-Connecting-IP` is served as the full app whatever
`TRAVEL_PUBLIC_SCOPE` says (tested: 200). It needs a tunnel "HTTP Host Header" override, which
the runbook forbids, but then rollback step 1 (scope back to `tracker`) wouldn't close the app.
Fix: in `is_reachable`, a request carrying `CF-Connecting-IP` whose Host isn't in
`TRAVEL_PUBLIC_HOSTS` answers 404.

**F-9. Production can start with scope `all` and no OIDC issuer.**
`backend/travel/core/exposure.py` (`production_problems`),
`backend/travel/accounts/provisioning.py` (`check_claims` skips the issuer comparison when
`OIDC_ISSUER` is empty). Sign-in can't work without discovery, so it fails closed in practice.
Fix: require an `https://` `OIDC_ISSUER` (and the client id and secret) when
`TRAVEL_PUBLIC_SCOPE=all`.

**F-10. Trips can be set to `public` through the API before T37.**
`backend/travel/trips/api.py` (`TripIn`, `TripPatchIn`, bulk edit). The UI hides "public"; the
API accepts it on create and update (tested). Nothing renders publicly yet, but T37's snapshot
builder would find rows marked public without its consent flow. Fix: answer 422 for `public`
(trips, bulk edit, purpose defaults) until T37, or note in item 38 that existing `public` rows
must not publish without fresh consent.

**F-11. The dev copy's pruning misses 14c's e2e leftovers.** `backend/travel/core/devcopy.py`
(`E2E_ROWS`, `_is_synthetic`). It prunes trips, places and device tokens named `E2E …`, but not
persons ("E2E Sheet Cousin"), the tag `e2e`, or the e2e trip-sheet batch: an `.xlsx` is a zip,
so the SYNTHETIC marker isn't in the first 4 KB of the decompressed raw file. The dev database
has none of these today (read-only count: 0 persons, 0 tags, 0 trip-sheet batches), so this
only matters if `./dev e2e` runs against the main stack before 40c-2's copy. Fix: extend
`E2E_ROWS` to `accounts_person.display_name` and `trips_tag.name` (case-insensitive), detect
trip-sheet batches by the workbook's `SYNTHETIC` title, and extend `e2e_cleanup` (already
queued in NEXT.md).

**F-12. The SPA shell, assets and source maps are served anonymously.**
`backend/travel/core/spa.py`, `backend/config/settings.py` (WhiteNoise before the login wall),
`frontend/vite.config.ts` (`sourcemap: true`). Confirms 40d's lead and widens it:
`/app/assets/<anything>` and `/app/icons/<anything>` return the shell (200), WhiteNoise serves
`/app/index.html` directly, and `/app/assets/*.js.map` (4.8 MB) is public. No data; the code is
public anyway. Fix: `spa_index` answers 404 for paths under `assets/` and `icons/` or with a
file extension; build without source maps for the production image (or delete `*.map` from
`spa_root`).

**F-13. API responses carry no Cache-Control.** `GET /api/v1/me` and the other JSON endpoints
send only `Vary: Cookie`. Cloudflare doesn't cache JSON by default, but a future "cache
everything" rule would. Fix: `Cache-Control: private, no-store` on `/api/` responses (tiles keep
their `private, max-age=300`).

**F-14. The landing page answers any method.** `backend/travel/accounts/views.py`
(`landing_view` has no method decorator; `TRACE /` answered 200). Fix: `@require_safe`.

**F-15. Container hardening gaps outside `web`.** `backend/Dockerfile` has no `USER` (a bare
`docker run` of the image is root; compose sets 1000:1000, verified in production);
`worker` isn't `read_only`; `db` and `backup` have no `pids_limit`; the production bulk
directory is mode 775. Fix: `USER 1000:1000` in the runtime stage, `read_only` plus `tmpfs` for
`worker`, `pids_limit` everywhere, bulk directory 750.

**F-16. Session housekeeping.** Every anonymous `/auth/login` stores a session (rate-limited to
30 per 10 minutes per address), and no job deletes expired sessions. Cookie names have no
`__Host-` prefix, so a sibling `*.adamcasada.com` site could set cookies for the app's host
(Django's login rotates the session key and CSRF checks the Origin, so this is hardening only).
Fix: a daily `clearsessions` job; `SESSION_COOKIE_NAME = "__Host-sessionid"` and
`CSRF_COOKIE_NAME = "__Host-csrftoken"` in production (the SPA reads the CSRF cookie by name).

**F-17. Test gaps.** No unit test for a replayed or missing `state` at `/auth/callback` (the
smoke covers a forged one: 400), for the session key changing at sign-in, or for every non-API
view under `/api/` refusing anonymous requests with and without a Bearer header. Fix: add them
to `tests/test_authentik.py` and `tests/test_auth.py`.

Not done: **Betterleaks (Q-12).** Pulling the unpinned `ghcr.io/betterleaks/betterleaks` image
was refused by the permission system. Item 41 can run it from a pinned digest once Adam allows
it. gitleaks v8.30.1 over the full history (231 commits, all refs): no leaks.

## What was checked and holds

- **Anonymous surface (scope `all`):** only `/`, `/healthz`, `/auth/login`, `/auth/callback`,
  the SPA's static files and the two ingest paths answer; `/t/`, `/u/`, `/pm/`, `/invite/`,
  `/request-access`, `/favicon.ico`, `/robots.txt`, `/static/…` answer 404 without DEBUG pages;
  every one of the 75 API operations answers 401; private pages redirect to sign-in; path tricks
  (`/api/v1/ingest/../me`, `//api/v1/me`, `%2f` in asset paths) reach nothing; 500 and 403 pages
  are Django's plain ones; unknown hosts are refused. The trips.* redirect keeps the path, takes
  its target from settings and isn't open (`//evil.example`, `?next=`).
- **OIDC (code and tests, no real issuer):** Authlib 1.9.1 sends state, nonce and PKCE S256 and
  validates the ID token's signature, `iss` (from discovery), `aud`, `exp`, nonce and `at_hash`;
  the app adds the `OIDC_ISSUER` match, `(iss, sub)` keying (never email), the group check
  (list only), the `amr` check and `auth_time` clamping. Sign-in rotates the session key
  (Django `login`); cookies are Secure, HttpOnly (session) and SameSite=Lax; logout is a CSRF-
  checked POST that flushes the session and ends Authentik's session with `id_token_hint`;
  re-authentication refuses a different user. `next` is checked with
  `url_has_allowed_host_and_scheme`. 226 targeted tests pass in this lane (auth, Authentik,
  exposure, production, account commands, dev copy).
- **Signed-in Member (HTTP spot checks):** a second Member and a Viewer get 404 on another
  Member's private trip, legs, stops, notes, route versions, upload session (GET, chunk PUT,
  DELETE) and tags, and 403 on adding legs, stops or route versions to a family trip they can
  see; raw history tiles are empty for everyone but the owner, the Admin included; the Admin
  can't see private trips, uploads or tokens of others and edits only trips visible to them
  (permissions.md §6.3); family responses carry display names only, no emails or identities
  (D-72, D-76); a deactivated account's live session answers 401.
- **Uploads:** per-kind size limits, quota counting open sessions, chunk size and SHA-256
  checks, stale-session sweep; trip sheets are size-, member- and unpacked-size-limited and
  parsed with defusedxml active in the image (CPython's zip reader also stops at the declared
  size).
- **Routing proxy:** per-user limits (10 per 10 s, bursts of 5), server-wide ORS and FOSSGIS
  limits, the ORS key only in the Authorization header, a generic User-Agent, waypoints only
  (rule 13); no direct provider calls from the frontend.
- **Production stack (read-only):** settings refuse to start without auth.md §7.7 (forced in
  compose.prod.yaml, checked by `production_problems`; `check --deploy` passes); `web` publishes
  `127.0.0.1:8784` only; the database publishes nothing; every container runs non-root with
  `cap_drop: ALL` and `no-new-privileges`; `web` is read-only with memory and pids limits;
  `.env.prod` is 0600 in a 0700 directory; images carry no secrets in their environment, history
  or files; production logs contain no token-, credential- or query-secret-shaped strings; the
  gunicorn access log records paths without query strings. Production currently runs commit
  `c1f4bb35a46e` with scope `tracker` (public host → 404), `OIDC_*` and `AGE_RECIPIENT` empty.
- **Dev stack and tunnel today:** the tunnel's current version routes only the tracker path on
  travel.* and trips.* to 8783 (nothing listens there while `ingest` is stopped); dev's
  `TRAVEL_PUBLIC_HOSTS` is empty and its DEBUG server answers a bare 404 to the public name.
